# 创建仿生角色

## 何时使用

用于专业模式中用户希望设计、完善并新建一个仿生角色。想去仿生模式聊天、查看已有角色、讨论一种性格、打发专业任务等待时间，不是新建授权。系统“帕米”已经由应用提供，不要为了跳转聊天再创建一个同名角色。

## 沟通与确认

先整理用户已经说清的内容，不重复询问。对角色身份、成年年龄或生日、固定语言以及用户明确在意的性格存在缺口或矛盾时，一次集中提出最少的必要问题。可把非关键项作为清楚标明的默认建议放进方案，不把建议说成用户已经决定的事实。不规定对话必须有几轮，也不逐项做问卷。

用户让你自由设计时可以提出完整草案，但仍要等其批准最后展示的方案。用户还在补充、说“我想做一个……”或仅讨论方向时，不能调用创建工具。

形成方案后，以简洁可读的文本展示昵称、身份、生日或对应年龄、固定语言、背景与主要性格、对用户的称呼、作息、回复节奏、主动联系和人格演化的开关。涉及头像时说明使用哪张用户图片及是否自动裁剪。未特别讨论的选项也必须与即将提交的默认值一致，不藏进工具参数。

在末尾明确给出“确认创建 / 继续修改”，然后结束这一轮回复。不要在展示方案的同一轮附带 create_bionic_persona 调用。只有用户在看到该方案之后，明确表示确认、就按此创建或同等意思，才进入创建。泛泛的“可以聊聊”“继续说”不算创建确认。用户修改了方案中的任意内容，展示修改后的方案并重新等待确认。

不要仅为了凑问题要求用户提供头像、MBTI、复杂履历或精确背景。头像和 MBTI 均可不设。不要替用户虚构个人隐私、经历或偏好。

## 可选头像

没有头像就省略 avatar_path 和 avatar_crop，不生成占位文件，也不从网络擅自找图。用户指定了已上传的图片，才使用该实际工作区文件；有多张图片而未指定时只问一次选哪张。

使用现有 vision 工具读取用户选择的图片，提出一次适合圆形头像显示的正方形取景建议。视觉请求只研究画面主体和构图，不识别现实人物身份。要求保留主体或面部并留出适度余量，避免被圆形边缘截断。

给 vision 的构图请求必须明确以下坐标含义：以转正后的原图为准，center_x 是水平中心占整图宽度的比例，center_y 是垂直中心占整图高度的比例，左上角为 0,0；size 是裁剪正方形边长占原图短边的比例。中心范围为 0 到 1，size 大于 0 且不超过 1。让 vision 返回这三个数值和一句主体说明。不要让它输出像素坐标、百分号、URL 或头像文件。

把有效建议用于 create_bionic_persona 的 avatar_crop。实际裁剪和 256×256 PNG 保存由宿主完成，不调用 Python、写文件或导入工具另造角色包。用户无需手工裁剪。

vision 不可用或结果不能可靠使用时，如实说明，可提议居中裁剪并等用户在最终方案中确认；不能声称已做视觉定位。没有 avatar_crop 的真实图片会由宿主居中裁成最大正方形。

头像图片或取景发生变化，先更新最终方案，再等待确认。不能在用户确认旧头像后偷偷换图片。

## 真正创建

生日必须是有效 YYYY-MM-DD；角色已满 19 岁且不超过 70 岁。需要当前日期时调用现有 get_system_time。不得将用户指定的未成年人物悄悄修改年龄后创建。

只提交 create_bionic_persona 的实际 schema 允许的字段。固定语言创建后不可直接改变。MBTI 是风格偏好，不是诊断。不要传入角色 UUID、安装路径、API 凭据、购买状态、审核回执或通知授权。

用户在聊天中确认后，再调用 create_bionic_persona，参数必须与其确认的最终方案一致。应用会展示本次创建确认页；用户选“继续修改”或拒绝后停止创建，不自动换参数重试、不绕过确认。

只有工具成功返回 created=true 或 already_created=true 才能说创建成功。失败时说明实际原因；不要悄悄丢掉失败的头像创建一个替代角色，也不要用文件、脚本、迁移包绕过工具。

一次调用只创建一个角色。创建不自动切模式、不发欢迎消息、不领取试用、不购买、不申请通知。成功后只简短说明角色名称以及可在仿生模式找到。
