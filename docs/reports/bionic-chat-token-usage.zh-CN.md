# 仿生聊天模拟使用的额度消耗分析报告

[English](bionic-chat-token-usage.en.md)

报告日期：2026-10-05。分析对象：Palmi 仿生模式，代码基线 [`12987237a22cecd2b1d0a9063e2e9c1970c6b1ce`](https://github.com/Hyp6666/PalmiAgent/tree/12987237a22cecd2b1d0a9063e2e9c1970c6b1ce)。计价模型：`deepseek-flash`，即当日官方文档中的 DeepSeek-V4.1-Flash。金额均为人民币；英文版按 [广发银行当日参考中间价](https://www.cgbchina.com.cn/searchExchangePrice.gsp) 折算为美元：1 美元兑 6.7104 元人民币，报价时间为北京时间 2026-10-05 14:35:26。

摘要：配置DeepSeek-Flash模型后，日常中高强度对话中，每人预估平均每周消耗3.21¥，其资金消耗量与做一次“创建一个HTML，用SVG画出鹈鹕骑自行车2D动画”模型能力测试[^1]的费用相当。本实验依据应用的上下文构造、工具协议及维护流程，以离线算法模拟每个场景中 100 名用户连续 7 天、每天主动发送 50 次消息的使用情况。主场景的输入 token 缓存命中率为 40.75%，100 人一周的估算模型费用为 ¥321.41；相同请求在全部输入均未命中时为 ¥522.04。实验未调用任何推理、聊天或嵌入 API。结果属于特定工作负载与缓存参数下的模拟估计，不是服务端实测，也不构成费用承诺。

## 1. 运行机制与上下文预算

仿生模式的 harness 是模型之外的宿主执行层，负责冻结本轮输入、构造请求、校验结构化工具输出、执行本地检索，并将通过校验的消息和投递状态持久化。人物归属、来源证据、人工记忆修订屏障及过期任务检查由宿主约束；模型输出不会直接成为未经校验的长期记忆。普通聊天开放 `recall` 与 `speak` 两个工具，要求工具调用，禁止并行调用，每轮最多允许 6 次生成尝试。一次 `speak` 可提交多个回复气泡，因此气泡数不等于模型请求数。相关实现见 [BionicCoordinator](https://github.com/Hyp6666/PalmiAgent/blob/12987237a22cecd2b1d0a9063e2e9c1970c6b1ce/PalmiAgent/Core/Bionic/BionicCoordinator.swift) 和 [BionicToolbox](https://github.com/Hyp6666/PalmiAgent/blob/12987237a22cecd2b1d0a9063e2e9c1970c6b1ce/PalmiAgent/Core/Bionic/BionicToolbox.swift)。

普通聊天请求的逻辑顺序如下。工具 schema 同时进入模型输入；其具体协议位置由供应商编码格式决定。

| 顺序 | 输入内容 | 更新条件 |
|---|---|---|
| 1 | 固定聊天指令、角色资料、当前本地用户资料 | 指令、角色或用户配置变更 |
| 2 | 最近角色日记、选中的完整记忆事实、人工修订屏障、过去对话摘要 | 日记写入、记忆增删改或压缩 |
| 3 | 压缩游标至本轮上界之间，按时间排列的已提交用户及角色消息正文 | 新消息提交或压缩游标推进 |
| 4 | `message_index`，含消息 ID、作者、时间、引用关系及待答消息定位 | 每轮重新构造 |
| 5 | 本地时钟、`prepared_reply` 未发送草稿、`reply_delivery` 投递信息 | 时间、草稿及投递状态变化 |
| 6 | 可选的 `recalled_evidence` 检索证据 | `recall` 执行后追加于尾部 |

进入上下文的长期记忆是所选记录的完整事实内容，而非全部数据库记录或仅标题摘要。选择顺序为偏好与边界、用户事实、承诺与未完成事项、共同事件，再按记录时间与 ID 排序，并按人物及主题去重；当前实现不根据本轮查询词重排这一前缀。超出预算的记录仍可由 `recall` 从本地档案检索。已提交的普通对话以正文消息回放，上一轮 `speak` 的原始工具参数及协议串不会原样保留为下一轮历史。上下文构造见 [BionicPromptBuilder](https://github.com/Hyp6666/PalmiAgent/blob/12987237a22cecd2b1d0a9063e2e9c1970c6b1ce/PalmiAgent/Core/Bionic/BionicPromptBuilder.swift)。

应用以近似计数器估算输入占用并控制记忆、日记和摘要预算；请求输出上限按 API 的 token 上限设置，供应商分词计费另行计算。近似计数将非空白 ASCII 字符合计除以 4 后向上取整，每个非 ASCII Unicode 标量计 1，并另计消息、工具及协议开销。聊天阈值取上下文上限的 90% 与“上下文上限减输出上限”中的较小值。模型当日公布的服务端上下文上限为 1M，并不改变应用的 200,000 本地限制。代码依据为 [BionicModels](https://github.com/Hyp6666/PalmiAgent/blob/12987237a22cecd2b1d0a9063e2e9c1970c6b1ce/PalmiAgent/Core/Bionic/BionicModels.swift)、[ApproximateTokenCounter](https://github.com/Hyp6666/PalmiAgent/blob/12987237a22cecd2b1d0a9063e2e9c1970c6b1ce/PalmiAgent/Core/Support/ApproximateTokenCounter.swift) 及 [DeepSeek 模型规格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

睡眠边界触发对话结算；容量不足时另行分段压缩。压缩提交摘要与有来源的记忆变更，人工修订屏障约束后续提案。最近日记属于角色虚构生活，旧日记单独压缩，不据此新增用户事实。默认关闭主动规划、性格演化及图像生成；本实验采用即时回复，默认睡眠区间为 01:00–08:00。

## 2. 实验设计

每个场景包含 100 个不同的合成用户，各自从空历史、空记忆的新角色开始，使用简体中文、成人设定、默认五维人格及 `Asia/Shanghai` 时区。观察区间为 2026-10-05 00:00 至 2026-10-12 00:00，不含结束时点。每人 350 次主动输入，每场景 35,000 次；7 个场景合计 245,000 次主动输入、285,670 次模拟模型请求。固定随机种子为 `20261005`，9 组缓存策略重放同一组请求，未重复生成用户对话。

用户与回复文本由中文日常话题模板生成。长度参数分别为用户 38 字符、每个回复气泡 48 字符；长文本场景改为 180 与 240。截取长度为 `max(3, floor(exp(N(log(m) − 0.25, 0.70²))))`，其中 `m` 为对应长度参数，另有 15% 的概率追加 1–29 的数字及句号；这些参数不等于实现后的精确平均长度。回复气泡数为 1、2、3、4、5 的概率依次为 50%、30%、13%、5%、2%。主场景实际产生 62,822 个气泡，平均每次主动输入 1.795 个。每轮以一次结束本轮的 `speak` 返回全部气泡。

主场景在 8% 的输入后先执行精确消息 ID 检索，返回 1–4 条合成档案中的旧消息，再发起模型请求完成回复。高检索场景将概率提高到 35%，其中 10% 的检索轮次连续执行两次检索。关键词场景使用话题词匹配，单页最多 20 条并生成游标；其消息与记忆检索是在离线程序中重建的近似逻辑，未执行完整 Swift 数据库实现。检索行为及 ID 选择由算法预定，未评估模型能否自主作出相同决策。

每日对话摘要的文本长度参数为 600 字符，上限 1,400 字符；日记为 400 字符，上限 2,400 字符。每日压缩提交 0、1、2 条模拟记忆提案的概率分别为 25%、55%、20%，事实正文取自合成用户消息。人工修订场景在每日第 9、25、41 次输入前修改记忆并更新修订屏障。这些设置用于估算序列长度与状态变化，不验证摘要质量、事实提取准确率或语义一致性。

消息时间按三种分布生成。主场景每日分 5 段发送 7、8、7、15、13 次消息；参考起点为 08:42、12:24、16:48、20:12、21:54，起点均匀偏移 ±25 分钟，各段消息均匀分布于之后 35 分钟。零散场景在 08:30–22:45 均匀采样；晚间场景按 `21:00 + 100 分钟 × Beta(1.4, 1.4)` 采样。排序后保证相邻主动消息至少间隔 30 秒。一个主场景样本日的 5 段区间为 08:29:45–08:57:02、12:27:10–12:53:43、16:35:45–16:56:29、20:01:07–20:24:06、22:11:17–22:37:56，分别包含上述数量的消息；该样本为合成记录。

每日首条消息前 5 分钟进入前台，完成前一日的睡眠结算与日记维护；末段聊天在 23:00 前结束。日记在 23:00 到期后于次日前台写入，因此观察区间内每人发生 6 次对话压缩、6 次日记写入及 3 次旧日记压缩。第七日的结算于观察区间结束后才发生，未计入本周费用。日记来源复现单页最多 20 条、正文 12,000 UTF-8 字节的档案限制，不假设整日对话均已进入日记请求。

计费 token 使用 [DeepSeek 官方 V4.1 分词器](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash) 与 [官方公开编码库](https://github.com/deepseek-ai/deepseek-recipe) 计算，未下载模型权重。分词器文件 SHA-256 为 `c90dfa01249db1be4245780a052ede752e1361c612ac6d08e2bdada7d599476b`，编码库采用发布包 `deepseek-recipe 0.1.1`。99 次完整分词对照与 98 次完整编码对照均无差异；另完成 7 项缓存规则检查、用户与请求类别合计核对，以及晚间费用的独立公式校验。这些检查验证离线实现内部一致性，公开编码格式与服务端实际部署仍可能不同。

## 3. 缓存模型与计价方法

缓存按精确 token 前缀匹配，只有已保存、已完成构建且未过期的完整前缀单元可命中。依据当日 [DeepSeek 缓存文档](https://api-docs.deepseek.com/guides/kv_cache/)，单元可在输入末尾、输出末尾、跨请求共同前缀以及长序列的周期位置形成。共同前缀须先发现并保存，才能用于后续请求；例如先后出现 `A+B` 与 `A+C` 时，不将第二次请求的共同部分 `A` 直接记为命中。离线实现使用压缩 token 前缀树，保存输入及输出端点，并按策略维护构建时间与最后使用时间。

官方只说明构建通常需要数秒，不使用的缓存一般保留几小时至几天，且为尽力提供的机制；未公布精确保留时间、周期长度、路由、容量及回收概率。主实验采用不活跃保留期 6 小时、周期 4,096 token、构建延迟 5 秒，均为假设参数。另假设生成与工具完成耗时 5 秒、连续工具请求间隔 6 秒，缓存构建从该步骤完成后开始计时；命中或重新保存更新最后使用时间。各角色从独立冷缓存开始，未计未知的跨角色或跨账户复用。应用虽有内部 `promptCacheKey`，直接 DeepSeek Chat Completions 路径不传递 OpenAI 的缓存键，不能据此假设固定服务端路由。

表 2. 当日 [官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，单位为每百万 token。

| 时段 | 命中输入 | 未命中输入 | 输出 |
|---|---:|---:|---:|
| 非高峰 | ¥0.02 | ¥1.00 | ¥4.00 |
| 高峰 | ¥0.04 | ¥2.00 | ¥8.00 |

高峰为北京时间周一至周五、排除中国法定节假日的 09:00–12:00 与 14:00–18:00。依据 [2026 年节假日安排](https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202511/t20251104_4258838.html)，本观察周的 10 月 5–7 日属于国庆假期，按非高峰计价；10 月 8–9 日适用工作日高峰窗口。10 月 10 日虽为调休工作日，仍属周六，按所述价格规则为非高峰。结果另列无节假日的普通周费用，保留相同星期与日内消息时间。

输入命中率按全部请求的 token 加权计算：`R = Σhᵢ / Σnᵢ`。逐请求费用为 `Cᵢ = [hᵢp_hit(tᵢ) + (nᵢ − hᵢ)p_miss(tᵢ) + oᵢp_out(tᵢ)] / 10⁶`，其中 `nᵢ`、`hᵢ`、`oᵢ` 分别为输入、命中输入及输出 token 数，单价按请求时间确定。工具 schema 计入输入，函数名、参数及输出协议计入输出；本地档案检索本身无独立模型费用，返回证据在后续输入中计费。输出上限为预算约束，不按上限预扣本实验账单。思考关闭，主结果未加入隐藏思考 token。

## 5. 敏感性分析与解释

表 5. 对同一主场景请求流改变缓存参数。未列出的参数保持为保留期 6 小时、周期 4,096 token、构建延迟 5 秒。

| 缓存参数 | 输入命中率 | 100 人本周费用 |
|---|---:|---:|
| 主参数组 | 40.75% | ¥321.41 |
| 保留期 3 小时 | 38.76% | ¥331.92 |
| 保留期 24 小时 | 41.38% | ¥318.21 |
| 保留期 72 小时 | 41.55% | ¥317.37 |
| 仅请求边界及共同前缀，无额外周期单元 | 40.68% | ¥321.79 |
| 周期 1,024 token | 41.19% | ¥319.19 |
| 周期 16,384 token | 40.68% | ¥321.79 |
| 构建延迟 1 秒 | 43.34% | ¥308.91 |
| 构建延迟 15 秒 | 40.75% | ¥321.41 |

所选参数得到 38.76%–43.34% 的命中率范围。这是参数敏感性范围，不是服务端命中率的置信区间。日内消息间隔通常短于保留期，因此三种短聊时间分布在主参数下命中率相同，但高峰请求数量不同，费用随之变化。日记、记忆及摘要更新会改变较早的前缀，随后需要重新预热；每轮尾部时钟变化并不会使此前未变的前缀全部失效。

首轮聊天输入的诊断分解为：固定或当日稳定前缀约 29.61%，历史正文约 14.68%，完整 `message_index` 约 50.98%，其余协议及运行时信息约 4.73%。分解按组件计数，边界协议归属存在少量差异，账单仍以完整请求分词为准。短消息正文较少时，反复重写的消息定位索引占输入的大部分；增加可复用正文可提高命中比例，但长文本场景总费用仍增加。提高检索频率会增加请求与证据输入，高命中率也不能单独证明费用较低。优化应优先核查定位索引的必要字段及稳定编码，在保持引用、人物归属和修订屏障正确性的前提下减少重复输入，并以线上计费数据验证收益。

若仅作输出价格敏感性计算，保持请求流不变、每个请求额外加入 512 或 1,536 个思考输出 token，100 人费用分别增加 ¥85.15 或 ¥255.46，总费用约 ¥406.56 或 ¥576.87，即每人 ¥4.07 或 ¥5.77。实际开启思考会改变延迟、输出及工具选择，本项不预测开启后的真实使用行为。

本实验未模拟真实语义决策、内容校验失败、网络重试、供应商缓存容量与路由变化、持续后台唤醒、主动规划或图像模型调用；角色配置、会话存量及使用频率变化也会改变结果。模板生成内容不能代表真人聊天分布，关键词检索及档案字段仅为近似重建。离线分词校验不能替代服务端 `usage` 遥测；线上应汇总 `prompt_cache_hit_tokens` 与 `prompt_cache_miss_tokens`，按模型、时段及请求类别核算。源代码版本、实验参数与上述结果可供方法核查，本文未附完整合成请求流，不能仅凭随机种子独立重建逐 token 结果。
